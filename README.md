# بوت واتساب Rust لتحميل فيديوهات YouTube

بوت غير رسمي مبني على [`whatsapp-rust`](https://github.com/oxidezap/whatsapp-rust) ومكتبة [`yt-dlp`](https://github.com/boul2gom/yt-dlp).

> هذا العميل غير رسمي وقد يخالف شروط WhatsApp أو YouTube. استخدمه على مسؤوليتك، ولا تستخدمه لتنزيل أو إعادة توزيع محتوى لا تملك حقه.

## المتطلبات

- Rust وCargo (الإصدار المحدد في `rust-toolchain.toml`).
- هذا الإصدار مخصص لـ **Linux x86-64** فقط، ويضمّن asset الرسمي `yt-dlp_linux` من إصدار [`2026.10.26`](https://github.com/yt-dlp/yt-dlp/releases/tag/2026.10.26) داخل `libraries/yt-dlp`. يتحقق البوت عند التشغيل من المعمارية والإصدار ويرفض الملف غير المطابق بدل تشغيل نسخة مختلفة.
- JavaScript runtime مدعوم لـ `yt-dlp`، مثل Node.js أو Deno أو Bun. يختار البوت تلقائيًا runtime متاحًا، أو يمكن ضبط `YTDLP_JS_RUNTIME`.
- لا يحتاج مسارا تنزيل الفيديو والصوت المنفصلان في هذا البوت إلى `ffmpeg`، ولا يستدعيانه.
- اتصال إنترنت لخدمات WhatsApp ومصدر الفيديو عند الاستخدام.
- رقم WhatsApp دولي في `.env`.

## التشغيل

```bash
cp .env.example .env
# ضع الرقم في WHATSAPP_PHONE_NUMBER
cargo run --release
```

يَظهر pairing code في الطرفية. بعد الربط تحفظ الجلسة في `whatsapp_bot.db`.

## حل خطأ YouTube: Sign in to confirm you’re not a bot

هذا الخطأ ليس خطأً في رابط الفيديو؛ YouTube يطلب جلسة متصفح موثوقة. صدّر Cookies لحسابك من متصفح محلي بصيغة Netscape، وانقل الملف إلى الخادم، ثم ضع مساره في `.env`:

```env
YTDLP_COOKIES=/opt/whatsapp-bot/youtube-cookies.txt
```

أو استخدم `YTDLP_COOKIES_FROM_BROWSER=chrome` إذا كان Chrome وملفاته متاحين للمستخدم الذي يشغّل البوت. لا ترفع ملف Cookies إلى Git ولا تشاركه؛ فقد يسمح بالدخول إلى حسابك. إذا استمر الخطأ، صدّر Cookies جديدة من نافذة متصفح عادية، وتأكد من أن الملف قابل للقراءة من مستخدم الخدمة.

بعد إضافة Cookies، أعد تشغيل البوت. لا توجد طريقة مضمونة لتجاوز تحقق YouTube بدون جلسة متصفح أو أن يرفع YouTube الحظر عن عنوان IP.

## أوامر YouTube

يدعم البوت صيغ YouTube الشائعة كلها، بما فيها:

- `youtube.com/watch?v=...` و`www.youtube.com/watch?v=...`
- `youtu.be/...` مع معاملات الوقت أو المشاركة
- `youtube.com/shorts/...`
- `youtube.com/live/...`
- `youtube.com/embed/...` و`youtube-nocookie.com/embed/...`
- `m.youtube.com/...` و`music.youtube.com/...`

يمكن أن يكون الرابط محاطًا بعلامات مثل `< >` أو موجودًا مع نص قصير في الرسالة؛ يستخرج البوت الرابط تلقائيًا ثم يمرره إلى `yt-dlp`.

1. أرسل رابط YouTube مع الأمر التالي لعرض الجودات والأحجام المتاحة:

```text
/yt https://www.youtube.com/watch?v=VIDEO_ID
```

يعرض البوت قائمة مرقمة للفيديو وقائمة مرقمة للصوت. يعرض الحجم فقط إذا وفّرت YouTube حجم الملف الدقيق؛ إذا لم يتوفر، تظهر عبارة «الحجم غير معروف» بدل تقديره. الرقم `0` يعني **عدم تنزيل** ذلك النوع. يحفظ البوت الرابط مؤقتًا داخل نفس المحادثة، لذلك لا تحتاج إلى إعادة إرساله.

2. اختر الجودتين وأرسل الأمر المختصر فقط:

```text
/yt <رقم_جودة_الفيديو> <رقم_جودة_الصوت>
```

أمثلة:

```text
/yt 0 4   # الصوت فقط
/yt 3 0   # الفيديو فقط
/yt 3 4   # كلاهما
```

يمكن أيضًا إرسال الجودة والرابط في رسالة واحدة عند الحاجة:

```text
/yt https://youtu.be/VIDEO_ID 3 4
```

## سلوك الملفات

- لا يتم دمج الفيديو والصوت.
- ينزّل البوت الفيديو وحده، ويرفعه إلى WhatsApp كـ **ملف Document**، ثم يحذف الملف المحلي.
- بعد ذلك ينزّل الصوت وحده، ويرفعه كـ **ملف Document**، ثم يحذف الملف المحلي.
- لا يرسل الفيديو كرسالة فيديو ولا الصوت كرسالة صوتية.
- أثناء الرفع تُحفظ نسخة التشفير في RAM متى سمحت الذاكرة المتاحة والسقف المحدد؛ وإلا يستخدم البوت ملفًا مؤقتًا على القرص. بعد نجاح الرفع أو فشله يحذف الملف الأصلي والنسخة الوسيطة، وعند إعادة التشغيل ينظف آثار تنزيلات البوت التي بقيت بعد توقف مفاجئ.

## تخفيف حمل المعالج في الاستضافة محدودة الموارد

- يقبل البوت **طلب تنزيل YouTube واحدًا فقط في الوقت نفسه**؛ تُرفض الطلبات المتزامنة برسالة تطلب إعادة المحاولة بعد اكتمال المهمة، بدل تشغيل عدة تنزيلات ورفوعات تتنافس على حصة المعالج.
- يضبط مدير التنزيل على ملف محافظ بمقطع تنزيل متوازٍ واحد ومخزن مؤقت أصغر.
- تُقاس نسبة استخدام CPU من إحصاءات cgroup v2 كل ثانية، وتُنعّم بـ **EMA** (ألفا الافتراضية `0.25`). أثناء تشفير ملف كبير قبل رفعه، يضيف البوت تأخيرًا قصيرًا بين كتل القراءة عندما تتجاوز EMA الهدف، ثم يزيل التأخير عندما ينخفض المتوسط.
- يستثني البوت مرحلة `/yt <الرابط>` — من جلب معلومات الفيديو حتى إرسال قائمة الجودات — من عينات EMA. عند استئناف القياس يعيد خط الأساس، كي لا تُحتسب هذه النافذة في متوسط استخدام CPU.
- تشفير الرفع يجري بتدفق، لكن وسيطه المشفر يُحفظ في RAM ضمن ميزانية آمنة للملفات الملائمة؛ ويعود تلقائيًا إلى ملف مؤقت على القرص للملفات الكبيرة أو عند انخفاض الذاكرة.

إعدادات اختيارية في `.env`:

```env
# هدف استخدام CPU المطبّع على حصة الحاوية (1-100). الافتراضي 55%.
CPU_EMA_TARGET_PERCENT=55
# وزن عينة CPU الجديدة في EMA (0.05-0.8). الافتراضي 0.25.
CPU_EMA_ALPHA=0.25
# أقصى حجم ملف لتشفيره في RAM (MB). الافتراضي 512؛ الصفر يعطل التشفير في الذاكرة.
UPLOAD_MEMORY_MAX_MB=512
# مستوى رسائل الطرفية: الافتراضي warn (تحذيرات وأخطاء فقط)، info للتفاصيل.
RUST_LOG=warn
```

سقف RAM الفعلي هو الأصغر بين `UPLOAD_MEMORY_MAX_MB` وربع الذاكرة المتاحة التي يبلّغ عنها cgroup أو النظام؛ النطاق القابل للضبط 0–4096 MB. لذلك يبقى نحو ثلاثة أرباع الذاكرة المتاحة احتياطيًا. إذا لم تتوفر قراءة موثوقة للذاكرة، أو لم يستطع النظام حجز المخزن، يستخدم البوت ملفًا مؤقتًا على القرص بدل المخاطرة بنفاد الذاكرة. بعد رفع كل ملف تُحرر الذاكرة تلقائيًا عند إسقاط المخزن.

رسائل الطرفية الافتراضية الآن على مستوى `warn`، فتظهر التحذيرات والأخطاء وتُخفى رسائل `info` و`debug`. غيّر `RUST_LOG=info` مؤقتًا إذا احتجت تفاصيل التشغيل، أو استخدم `RUST_LOG=error` لتقليل الرسائل أكثر.

اضبط هدف CPU أقل من حد الاستضافة الفعلي بهامش مناسب. إذا لم توفر البيئة ملفات إحصاءات cgroup v2، تبقى حدود التزامن والتنزيل المحافظ فعّالة، لكن لا يعمل التكيّف المبني على قياس CPU. لا يمكن لهذه الآلية ضمان البقاء دون حدّ يفرضه مزود الاستضافة، لأنها لا تستطيع إيقاف طلب تنزيل جارٍ بالكامل، لكنها تمنع تراكب الأعمال وتخفف التشفير تلقائيًا عند استمرار ارتفاع المتوسط.

## الملاحظات الأمنية

- لا ترفع `.env` أو `whatsapp_bot.db` أو مجلد `libraries/` إلى مستودع عام.
- pairing code وملف قاعدة البيانات بيانات حساسة.
- قد تفرض WhatsApp حدودًا على حجم الملفات أو عدد الرسائل.
